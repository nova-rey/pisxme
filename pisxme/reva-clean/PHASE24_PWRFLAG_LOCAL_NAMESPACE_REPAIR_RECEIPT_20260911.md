The two live PWR_FLAG instances used `power:PWR_FLAG` while their embedded
definitions differed from the installed library copy. A complete disposable
probe changed every embedded PWR_FLAG definition and live instance to the
project-local `PiSXMeRevAClean:PWR_FLAG` namespace.

Native KiCad 10.0.5 ERC changed from 485 warnings / 0 errors to **483
warnings / 0 errors**. Both `lib_symbol_mismatch` findings disappeared, no
new findings or errors appeared, hierarchy structure passed, and the exported
netlist `(nets)` section retained exact names and `(ref,pin)` node sets after
normalizing autogenerated codes.

The validated transformation was promoted to the root embedded definition,
the live CORE_CM5 and POWER_INPUT instance `lib_id` fields and their active
embedded definitions, and the project-local symbol library. An unused legacy
definition remains in the CORE_CM5 serialization but is not referenced by a
live instance and produces no native mismatch. This is a source/library
repair, not a waiver. **CLOSED — embedded PWR_FLAG library-integrity root
cause.**
